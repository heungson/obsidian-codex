# v0.2.0: Claude Code CLI 지원

입력창 아래 **모델 · 추론 강도** 버튼의 Provider에서 Codex CLI와 Claude Code CLI를 선택할 수 있습니다. 명령 팔레트의 **Codex: Use Claude Code CLI / Use Codex CLI**도 지원합니다. 각 공급자의 모델·권한·마지막 대화는 따로 보관하고, 전환 시 작성 중인 입력과 첨부는 지웁니다. 기존 Claude 로그인과 설치된 CLI를 사용하며 자격 증명을 읽거나 저장하지 않습니다.

**업그레이드는 ZIP 폴더 전체를 복사하세요.** `main.js`, `claude-sdk.cjs`, `manifest.json`, `styles.css`, `THIRD_PARTY_NOTICES.md`, `LICENSE`를 함께 설치해야 합니다. 런타임 npm 설치와 CLI 자동 다운로드는 없습니다. CLI 자체는 별도 설치가 필요합니다.

Claude의 읽기 전용은 제한된 도구 목록과 실행 전 차단 훅으로 쓰기·셸·에이전트·알 수 없는 MCP 도구를 막습니다. OS 샌드박스는 아닙니다. Manual approvals는 기존 Claude 허용/거절 규칙을 따르며 미해결 요청을 패널에서 승인·거절합니다. 설정된 사용자/프로젝트 훅은 기존 CLI 설정의 일부로 실행될 수 있습니다. Bypass approvals 선택에는 확인이 필요합니다.

Claude에서는 스트리밍, 대화 이어가기·이름 변경·분기, 중단, 질문·도구 승인, 복사·노트 저장, 실제 Git 변경 스냅샷 검토를 지원합니다. 보관은 이 보관함의 플러그인 목록에서 숨기는 설정이며 CLI 기록을 옮기거나 삭제하지 않습니다. 실행 중 추가 지시(Steer), 수동 압축, 전용 MCP 입력 창, 안정적인 구독 사용량 제한 조회는 제공하지 않습니다. 중단/완료 후 같은 대화에 후속 질문을 보낼 수 있습니다. Claude 스킬은 `/skill-name` 문법을 사용합니다.

현재 CLI/SDK 호환성, 공급자별 기능 차이와 최신 설치 설명은 [영문 README](README.md), SDK 이용 조건은 [서드파티 고지](THIRD_PARTY_NOTICES.md)를 참고하세요. 아래 기존 설명의 Codex 권한·보관·리뷰 기능은 Codex 공급자에 해당합니다.

# Obsidian Codex

Obsidian 데스크톱에서 **설치된 Codex CLI와 기존 로그인**을 사용하는 네이티브 사이드바 플러그인입니다. 노트와 선택 영역을 첨부하고, 답변을 스트리밍으로 읽으며, 승인·계획·도구 실행·파일 변경과 저장된 대화를 관리할 수 있습니다.

비공식 커뮤니티 플러그인입니다. OpenAI 또는 Obsidian의 공식 확장 프로그램이 아닙니다. 로컬 Codex 기능을 연결하며, VS Code의 UI 전체를 이식하지는 않습니다.

## 빠른 설치

필요한 환경: Obsidian 데스크톱 1.8 이상, 설치된 Codex CLI, Codex 로그인. 현재 구현은 macOS의 Codex CLI **0.164.0**에서 생성한 프로토콜과 대조했습니다. Codex app-server의 실험 API가 사용되므로 CLI 업데이트에 따라 조정이 필요할 수 있습니다.

1. 터미널에서 `codex --version`을 확인하고, 필요한 경우 `codex login`으로 로그인합니다. API 키를 플러그인에 입력할 필요가 없습니다.
2. 릴리스 ZIP의 `obsidian-codex` 폴더 전체를 보관함의 `.obsidian/plugins/` 안에 복사합니다. `main.js`, `claude-sdk.cjs`, `manifest.json`, `styles.css`, `THIRD_PARTY_NOTICES.md`, `LICENSE`를 함께 설치합니다.
3. Obsidian을 다시 열거나 플러그인 목록을 새로 고친 뒤 **설정 → 커뮤니티 플러그인 → Codex**를 켭니다. 필요한 경우 제한 모드를 해제합니다.
4. 리본의 로봇 아이콘 또는 명령 팔레트의 **Codex: Open chat**을 실행합니다.
5. 모델·추론 강도·권한·작업/계획 모드를 선택하고 질문을 전송합니다. 기본 권한은 **Read-only**입니다.

직접 빌드해서 설치하려면:

```sh
npm ci --omit=optional
npm rebuild esbuild
npm run check
node scripts/install.mjs "/absolute/path/to/your/vault"
```

설치 스크립트는 플러그인 실행 파일과 SDK 런타임·라이선스/고지를 복사합니다. 기존 파일은 시간 표시가 있는 폴더에 백업하며, 다른 플러그인이나 활성화 설정은 바꾸지 않습니다. 활성화는 Obsidian 설정에서 수행합니다.

## 사용법

- **+ → Attach active note**: 현재 노트의 텍스트 스냅샷을 첨부합니다. 편집기에 있는 저장 전 텍스트도 포함됩니다.
- **+ → Attach selection**: 현재 노트에서 선택한 텍스트를 첨부합니다. 명령 팔레트의 **Codex: Attach selection to chat**도 사용할 수 있습니다.
- **+ → Attach file or image**: 보관함의 텍스트 파일 또는 이미지를 명시적으로 선택합니다. 이미지 입력을 지원한다고 모델 목록에 표시된 모델에서 PNG/JPEG/WebP/GIF를 첨부할 수 있습니다. 이미지당 최대 10 MiB, 메시지당 최대 8장입니다.
- 첨부한 텍스트는 질문과 구분되는 인용 자료로 전달됩니다. 대화에는 질문과 접을 수 있는 **Attached context**가 표시됩니다. 첨부는 다음 전송 한 번에 사용되며, 자동으로 매번 다시 첨부되지 않습니다.
- **⌘+Enter / Ctrl+Enter**로 전송합니다. 실행 중에는 **Steer**로 추가 지시를 넣고 **Stop**으로 중단을 요청할 수 있습니다.
- **History**는 현재 작업 폴더의 저장된 Codex 대화를 검색하고 불러옵니다. 보관된 대화 표시를 켜서 복원할 수도 있습니다. 긴 대화는 최근 30턴부터 불러오며 **Load earlier messages**로 이전 기록을 읽습니다.
- **⋯** 메뉴에서 이름 변경, 분기, 보관, Git 변경 검토, 컨텍스트 압축, 복사, 노트 내보내기, 계정·사용량·스킬·MCP 정보를 사용할 수 있습니다.
- 대화 내보내기와 대화 전체 복사는 페이지로 나뉜 이전 기록까지 읽습니다. 실행 중에 내보낸 내용은 그 시점의 스냅샷입니다. 최신 답변만 복사하거나 노트로 저장할 수도 있습니다.
- 명령과 도구 결과는 접힌 세부 항목으로 표시됩니다. 파일 변경에는 diff와 보관함 파일을 여는 버튼이 표시됩니다. 보관함 밖의 파일은 경로와 변경 내용만 표시됩니다.

`/ Commands` 메뉴에서 사용 가능한 로컬 명령을 찾을 수 있습니다.

| 명령       | 동작                                         |
| ---------- | -------------------------------------------- |
| `/new`     | 새 대화                                      |
| `/history` | 기록 검색·복구                               |
| `/review`  | 현재 작업 폴더의 커밋되지 않은 Git 변경 검토 |
| `/skills`  | 현재 작업 폴더에서 발견한 스킬 보기          |
| `/mcp`     | 설정된 MCP 서버·도구·인증 상태 보기          |
| `/status`  | 계정·사용량 제한 정보 보기                   |
| `/export`  | 대화 전체를 보관함 노트로 저장               |
| `/help`    | 명령 도움말                                  |

이 명령들은 Obsidian 클라이언트의 동작입니다. Codex 터미널의 모든 슬래시 명령을 대체하지 않습니다. 스킬은 일반 프롬프트에서 `$스킬이름`으로 요청할 수 있으며, 실제 검색·호출은 Codex 엔진이 처리합니다.

## 권한과 데이터

| 모드                     | 로컬 도구 권한                                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------------------- |
| **Read-only** (기본값)   | 파일을 읽고 분석합니다. 쓰기·제한 밖 실행은 승인 요청이 필요합니다.                                |
| **Agent · folder edits** | 작업 폴더 안에서 파일을 변경할 수 있습니다. 네트워크와 폴더 밖 작업은 필요 시 승인을 요청합니다.   |
| **Full access**          | Codex 샌드박스 제한을 해제하고 승인 없이 명령을 실행합니다. 선택 시 명시적인 확인 창을 표시합니다. |

권한은 새 턴마다 명시적으로 전달하여 기존 CLI 기본 설정에 의존하지 않습니다. 검토를 시작할 때에도 현재 선택한 권한을 적용합니다. 실행 중인 턴의 모델·권한·계획 모드는 변경할 수 없으며, 중단하거나 완료한 후 바꿉니다. 조직의 관리 정책이나 운영체제 샌드박스 설정에 따라 일부 모드는 거부될 수 있습니다.

승인은 명령·작업 폴더·이유와 전체 요청 세부 내용을 보여줍니다. 닫기 또는 취소는 거절로 처리됩니다. 플러그인은 알 수 없는 서버 요청을 자동 승인하지 않습니다. 추가 권한은 해당 턴에만 허용하며, 영구 정책을 자동으로 기록하지 않습니다. 사용자 입력 요청과 일반 MCP 폼·URL 인증 요청도 별도 창에서 응답합니다.

보관함 전체 텍스트를 플러그인이 자동 첨부하지 않습니다. 다만 Codex는 선택한 권한과 작업 폴더에 따라 도구로 파일을 읽을 수 있으므로, **명시적 첨부만 읽는 격리된 채팅은 아닙니다**. 첨부한 파일·질문·도구로 읽은 내용은 기존 Codex 서비스 설정과 데이터 정책에 따라 처리됩니다.

로그인 자격 증명은 Codex CLI가 관리합니다. 플러그인은 로그인 파일을 읽거나 토큰·비밀번호를 보관함에 저장하지 않습니다. Obsidian의 플러그인 `data.json`에는 실행 파일 경로, 작업 폴더, 모델·권한 선택, 마지막 대화 ID 등의 설정만 저장합니다. 대화 기록은 Codex가 관리하며, **Export**를 실행하면 선택한 내보내기 폴더에 Markdown 사본이 생깁니다.

패널을 닫거나 플러그인을 해제하면 소유한 app-server 프로세스를 종료합니다. 다시 열면 저장된 대화를 복구합니다. 연결이 끊어진 요청을 자동으로 재전송하지 않습니다. 시간 초과 이후에는 작업의 실제 결과가 불분명할 수 있으므로, 재연결해서 기록을 확인한 후 재시도합니다.

## 설정과 문제 해결

**CLI를 찾지 못할 때:** macOS의 GUI 앱은 터미널과 `PATH`가 다를 수 있습니다. 터미널에서 `which codex`로 찾은 **절대 경로**를 **설정 → Codex → Codex executable**에 입력한 다음 재연결합니다. 빈 값이면 `/opt/homebrew/bin`, `/usr/local/bin`, `~/.local/bin`, `~/.npm-global/bin`, 일반 PATH 및 Codex.app 리소스를 확인합니다. `~`로 시작하는 홈 경로는 지원합니다. 실행 파일 문자열에 명령 인자나 셸 스크립트를 입력하지 마세요.

**로그인/계정 문제:** 터미널에서 같은 사용자·같은 Codex 설정으로 `codex login`을 수행합니다. 플러그인의 `/status`에서 계정 상태를 확인할 수 있습니다. 새 로그인 창과 자격 증명 입력 UI는 제공하지 않습니다.

**다른 프로젝트에서 작업:** Working folder에 기존의 절대 폴더 경로를 입력하고 재연결합니다. 기본값은 현재 보관함입니다. 기록 목록도 이 폴더 기준으로 필터링합니다. 노트/이미지 첨부는 계속 현재 보관함에서 선택합니다. 폴더 변경 후에는 새 대화를 시작하는 편이 명확합니다.

**Git 검토 실패:** 작업 폴더가 Git 저장소인지 확인합니다. 코드 리뷰가 지원되지 않는 저장소에서는 일반 프롬프트에 검토할 텍스트를 첨부합니다.

**연결 오류/시간 초과:** `⋯ → Reconnect`를 실행합니다. 요청은 자동 재시도하지 않습니다. 접수 전에 거절된 질문은 입력창에 유지됩니다. 접수 후 오류가 발생했다면 이미 실행된 작업이 있을 수 있으므로 대화를 확인한 뒤 재시도하세요. 프로토콜과 맞지 않는 CLI 버전에서는 최신 호환 빌드를 사용하세요.

**긴 첨부:** 기본 전체 텍스트 첨부 한도는 60,000자입니다. 설정에서 1,000–500,000자 범위로 바꿀 수 있습니다. 큰 노트는 필요한 부분을 선택해서 첨부하면 더 적은 컨텍스트를 사용합니다. 크기 제한은 토큰 예산을 보장하지는 않습니다.

## 개발·검증

```sh
npm ci --omit=optional
npm rebuild esbuild
npm run check       # TypeScript + protocol/session tests + production bundle
npm run dev         # rebuild on source changes
npm run bundle      # dist/obsidian-codex-0.3.1.zip
```

- `src/protocol.ts`: JSONL 전송, 프로세스 수명, 요청 ID·타임아웃·서버 요청, 실행 파일 발견, 권한 매핑.
- `src/session.ts`: 완료/시작 이벤트 경합 방지와 명시적 첨부 입력 생성.
- `src/main.ts`: Obsidian ItemView, 설정, 기록·승인·입력 창, Markdown·도구·diff 렌더링.
- `tests/`: 가짜 app-server 프로세스를 이용한 순서가 뒤바뀐 응답·부분 프레임·잘못된 JSON·타임아웃·종료·재연결·서버 요청 테스트와 정책·첨부·턴 경합 테스트. 계정이나 네트워크 없이 실행합니다.

프로토콜은 설치된 CLI에서 다음과 같이 확인할 수 있습니다.

```sh
codex app-server generate-ts --experimental --out /tmp/codex-protocol
codex app-server generate-json-schema --experimental --out /tmp/codex-schema
```

공식 자료: [Codex app-server 프로토콜](https://learn.chatgpt.com/docs/app-server), [Obsidian 플러그인 개발](https://docs.obsidian.md/Plugins/Getting%20started/Build%20a%20plugin).

플러그인 소스는 MIT 라이선스이며, Claude SDK는 별도 이용 조건이 적용됩니다. `claude-sdk.cjs`와 THIRD_PARTY_NOTICES.md를 포함한 릴리스 폴더 전체를 설치하세요. 런타임 npm 설치는 필요하지 않습니다.
